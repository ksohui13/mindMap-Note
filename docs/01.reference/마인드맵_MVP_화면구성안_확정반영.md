# 마인드맵 웹앱 MVP 화면 구성안

## 1. 한 줄 핵심 정리

**PRD상 UI는 6개로 정의되어 있으나, 실제 화면 설계 기준으로는 `노드 상세 전체화면`을 별도 화면 상태로 분리하여 총 7개 화면으로 구성하는 것을 권장한다.**

---

## 2. 전체 화면 구성

| 번호 | 화면 | 유형 | 주요 목적 |
|---|---|---|---|
| 01 | 로그인 / 회원가입 | Page | 사용자 인증 |
| 02 | 마인드맵 대시보드 | Page | 마인드맵 조회·생성·관리 |
| 03 | 마인드맵 편집기 | Page | 노드 생성·편집·탐색 |
| 04 | 노드 상세 패널 | Panel | 선택 노드 Markdown 작성 |
| 05 | 노드 상세 전체화면 | Page / Overlay | 긴 Markdown 집중 편집 |
| 06 | 삭제 확인 | Modal | 마인드맵/노드 삭제 확인 |
| 07 | Markdown 내보내기 | Modal | 내보내기 범위 선택 및 실행 |

### 화면 수 산정 기준

PRD에는 로그인/회원가입, 대시보드, 마인드맵 편집기, 노드 상세 패널, 삭제 확인 모달, 내보내기 모달까지 총 6개 화면이 정의되어 있다.

다만 노드 상세 패널에는 **전체 화면 편집 모드로 확장**하는 요구사항이 있으며, 전체 화면 종료 시 기존 캔버스 위치와 선택 노드 상태를 유지해야 하는 별도 UX가 존재한다.

따라서 화면 설계 및 Figma 관리 기준에서는 **노드 상세 전체화면을 별도 화면 상태로 분리하여 총 7개 화면으로 관리하는 것이 적절하다.**

---

# 01. 로그인 / 회원가입

## 목적

비로그인 사용자를 인증하고 개인 마인드맵 영역으로 진입시키는 화면.

## 지원 기능

- 이메일 입력
- 비밀번호 입력
- 로그인
- 회원가입
- 로그인 ↔ 회원가입 전환
- 입력값 Validation
- 로그인/회원가입 실패 메시지
- 인증 성공 시 대시보드 이동

## 주요 상태

```text
01-1 로그인
01-2 회원가입
01-3 인증 오류
01-4 입력 Validation 오류
```

로그인과 회원가입은 별도 페이지로 분리하지 않고 하나의 인증 화면에서 전환하도록 구성한다.

# 02. 마인드맵 대시보드

## 목적

사용자가 자신이 만든 마인드맵을 조회하고 관리하는 서비스의 Home 화면.

## 지원 기능

### 마인드맵 조회

- 마인드맵 목록
- 제목 표시
- 최근 수정일 표시
- 노드 개수 표시
- 최근 수정순 정렬

### 마인드맵 생성

- `[+ 새 마인드맵]`
- 클릭 즉시 `새로운 마인드맵 N` 생성
- `N`은 해당 사용자가 현재 보유한 마인드맵의 **최대 번호 + 1**
- 가장 큰 번호가 삭제된 경우 해당 번호는 다시 사용 가능
- 중간에 비어 있는 번호는 별도로 찾아 재사용하지 않음
- 루트 노드 `시작` 생성
- 생성 후 Editor로 바로 이동

### 마인드맵 관리

- 마인드맵 열기
- 이름 변경
- Markdown 내보내기
- 삭제

### 계정

- 사용자 메뉴
- 로그아웃

## 새 마인드맵 생성 흐름

```text
[+ 새 마인드맵]
      ↓
새로운 마인드맵 N 생성
      ↓
루트 노드 "시작" 생성
      ↓
편집기 진입
      ↓
루트 노드 Edit Mode + 자동 Focus
```

별도의 새 마인드맵 제목 입력 모달은 제공하지 않는다.

## 주요 상태

```text
02-1 마인드맵 존재
02-2 마인드맵 0개 / Empty State
02-3 제목 Inline Edit
02-4 더보기 메뉴 Open
```

## 마인드맵 번호 생성 규칙

```text
현재: 1, 2, 3
3 삭제
현재 최대 번호: 2
다음 생성: 새로운 마인드맵 3
```

```text
현재: 1, 3
현재 최대 번호: 3
다음 생성: 새로운 마인드맵 4
```

즉, **현재 존재하는 최대 번호 + 1** 정책을 사용한다.

Empty State는 별도 화면으로 분리하지 않고 대시보드의 Variant로 관리한다.

# 03. 마인드맵 편집기

## 목적

마인드맵의 구조를 생성·수정·탐색하는 Main Workspace.

MVP에서 가장 중요한 핵심 화면이다.

## 지원 기능

### A. 상단바

- 대시보드로 돌아가기
- 마인드맵 제목 표시
- 마인드맵 제목 수정
- 빈 제목 Validation
- 저장 상태 표시
  - 저장 중…
  - 저장 완료
  - 저장 실패 · 다시 시도
- 더보기 메뉴
- 전체 마인드맵 Markdown 내보내기

### B. 캔버스

- 루트 노드 표시
- 일반 노드 표시
- 부모-자식 연결선
- 선택 노드 강조
- 캔버스 Pan
- Zoom In / Out
- 화면 맞춤

### C. 노드 생성

- `[+]` 버튼으로 자식 노드 추가
- 부모 주변 기본 위치에 생성
- 생성 즉시 Edit Mode
- 빈 제목 생성 방지

### D. 노드 편집

```text
더블클릭 → Edit Mode
Enter     → 변경 확정
Esc       → 변경 취소
```

- 공백만 입력된 제목 금지
- 편집 취소 시 기존 제목 복원
- 루트 노드 제목 수정 가능

### E. 노드 이동

- Drag & Drop
- 드래그 중에는 프론트엔드 위치만 변경
- Drag End 시 서버에 최종 위치 저장
- 저장 상태 표시
- 드래그로 부모 관계는 변경하지 않음

### F. 노드 관리

노드 More Menu:

```text
이름 변경
하위 트리 접기/펼치기
이 노드부터 내보내기
삭제
```

루트 노드는 삭제할 수 없다.

### G. 대규모 마인드맵 탐색

마인드맵당 최대 1,000개 노드 관리 목표를 고려하여 다음 UX를 지원한다.

- 하위 트리 Collapse / Expand
- 화면 밖 노드 렌더링 제어
- 필요한 영역 중심 로딩
- 현재 표시 영역 기준 Fit View

### H. 사용자 체감 성능 기준

- 편집기 진입 시 사용자가 최초로 보게 되는 노드 영역은 **2초 이내 표시를 목표**로 한다.
- 네트워크 및 데이터 조회를 포함하더라도 **최대 5초 이내에는 사용 가능한 화면을 표시**한다.
- 1,000개 전체 노드를 동시에 렌더링하는 것을 의미하지 않는다.

# 04. 노드 상세 패널

## 목적

마인드맵 편집기에서 선택한 노드의 상세 Markdown 문서를 작성하는 영역.

페이지 자체라기보다는 Editor 내부의 주요 UI 상태로 본다.

## 지원 기능

- 현재 선택 노드 제목 표시
- Markdown 입력
- Markdown Preview
- Markdown 자동저장: 마지막 입력 후 **2초 debounce**
- 저장 상태 표시
- 전체화면 확장
- 패널 닫기

## 동작 흐름

```text
노드 A 선택
      ↓
오른쪽 Detail Panel
      ↓
노드 A의 Markdown 로드
```

다른 노드를 선택하면:

```text
노드 A → 노드 B 선택
           ↓
Detail Panel 내용도
노드 B의 내용으로 변경
```

# 05. 노드 상세 전체화면

## 목적

긴 Markdown 문서를 작성할 때 마인드맵 캔버스의 방해 없이 집중하여 문서를 작성하는 화면.

PRD상 노드 상세 패널의 확장 기능이지만, 화면 설계에서는 별도의 화면 상태로 관리하는 것을 권장한다.

## 지원 기능

- 노드 제목 표시
- Markdown Editor
- Markdown Preview
- Editor / Preview 전환 또는 분할
- 자동저장
- 저장 상태 표시
- 전체화면 종료
- 기존 마인드맵으로 복귀

## 중요 UX

전체화면 종료 시 다음 상태를 가능한 한 유지한다.

```text
Mindmap
 └ 노드 A 선택
     ↓
상세 전체화면
     ↓
닫기
     ↓
Mindmap
 ├ 노드 A 선택 상태 유지
 ├ 기존 Zoom 유지
 └ 기존 Canvas 위치 유지
```

# 06. 삭제 확인 모달

하나의 공통 Modal 컴포넌트로 구성하되, 삭제 대상에 따라 두 가지 Variant를 제공한다.

## 06-A. 마인드맵 삭제

예시:

```text
'금융 공부' 마인드맵을 삭제하시겠습니까?

마인드맵과 포함된 모든 노드가 삭제됩니다.

[취소] [삭제]
```

### 지원 기능

- 삭제 대상 제목 표시
- 삭제 영향 안내
- 취소
- 삭제
- 삭제 성공 후 대시보드 갱신

## 06-B. 노드 삭제

예시:

```text
'예금' 노드를 삭제하시겠습니까?

하위 개념 5개도 함께 삭제됩니다.

[취소] [삭제]
```

### 지원 기능

- 삭제 대상 노드 표시
- 하위 노드 개수 표시
- 하위 트리 삭제 경고
- 취소
- 삭제

### 루트 노드

루트 노드는 삭제할 수 없으므로 삭제 메뉴 자체를 노출하지 않는 구성을 권장한다.

# 07. Markdown 내보내기 모달

## 목적

마인드맵 전체 또는 특정 노드 범위를 Markdown 파일로 변환한다.

## 진입점

```text

 → 마인드맵 전체 내보내기

 → 마인드맵 전체 내보내기
```

## 지원 범위

- 전체 마인드맵
- 현재 노드만
- 현재 노드 + 모든 하위 개념

## 지원 기능

- Export 범위 선택
- 대상 마인드맵/노드 표시
- 포함될 내용 설명
- `.md` 파일 생성
- Export 취소

## 기본 선택값

### 마인드맵 단위에서 진입

```text
● 전체 마인드맵
○ 현재 노드
○ 현재 노드 + 하위 개념
```

### 노드 단위에서 진입

```text
○ 전체 마인드맵

```

# 4. 별도 화면으로 만들지 않는 기능

다음 기능은 새로운 Page로 분리하지 않고 기존 화면의 상태 또는 컴포넌트로 처리한다.

| 기능 | 처리 방식 |
|---|---|
| 새 마인드맵 생성 | Dashboard → Editor 즉시 이동 |
| 마인드맵 제목 변경 | Inline Edit |
| 노드 제목 변경 | Inline Edit |
| 노드 추가 | Editor 내 Node 상태 |
| 노드 접기/펼치기 | Node 상태 |
| 저장 중 | Topbar Status |
| 저장 완료 | Topbar Status |
| 저장 실패 | Topbar Status + Retry |
| Zoom / Pan | Canvas Control |
| 노드 메뉴 | Dropdown |
| 사용자 메뉴 | Dropdown |
| 대시보드 Empty | Dashboard Variant |
| 루트 노드 최초 입력 | Editor Initial State |

이러한 상태를 모두 별도 화면으로 분리할 경우 화면 설계서가 불필요하게 커질 수 있으므로, **Screen과 State를 구분하여 관리한다.**

# 7. 디자인 우선순위

MVP에서는 다음 순서로 화면을 설계하는 것을 권장한다.

```text
1. 03 마인드맵 편집기
        ↓
2. 04 노드 상세 패널
        ↓
3. 02 대시보드
        ↓
4. 05 노드 상세 전체화면
        ↓
5. 01 로그인 / 회원가입
        ↓
6. 06 삭제 확인 모달
        ↓
7. 07 Markdown 내보내기 모달
```

### 이유

사용자가 실제로 가장 많은 시간을 보내는 화면은 마인드맵 편집기이며, 주요 사용 경험인 다음 기능이 대부분 편집기와 상세 패널에서 결정된다.

- 노드 생성
- 노드 편집
- 노드 이동
- 트리 탐색
- 상세 문서 작성
- 자동저장
- 저장 상태

따라서 UI 설계 초기에 **편집기 + 상세 패널의 UX를 먼저 확정**하는 것이 효율적이다.

# 8. 핵심 요약

**MVP의 주요 화면은 총 7개로 구성하고, 저장 상태·편집 상태·Empty State·메뉴 등의 변화는 새로운 화면이 아니라 각 화면의 State/Variant로 관리한다.**

추가 확정 기준은 다음과 같다.

- `새로운 마인드맵 N`은 현재 존재하는 최대 번호 + 1
- 상세 Markdown 자동저장은 2초 debounce
- 최초 가시 영역은 2초 이내 표시 목표, 사용 가능한 화면은 최대 5초 이내
